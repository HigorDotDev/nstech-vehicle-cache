# 01 — C4 Model

Status: **Final** — checked against `k8s/`, `devspace.yaml` and `justfile` (rule: diagrams show exactly what `just e2e` runs; anything else is labelled).

## Level 1 — System Context

```mermaid
C4Context
    title System Context — CDC-driven vehicle cache

    Person(reader, "Cache reader", "Tracking UI, alerting, risk rules (simulated by the e2e verifier)")
    System_Ext(writers, "Fleet write path", "Apps that register vehicles and ingest GPS positions (simulated by mock writers)")
    System(cache, "Vehicle Cache", "Keeps current state + latest position per vehicle, derived only from CDC")
    SystemDb_Ext(opdb, "Operational DB", "PostgreSQL: vehicles, positions")

    Rel(writers, opdb, "INSERT / UPDATE / DELETE", "SQL")
    Rel(cache, opdb, "Captures changes from the WAL", "logical replication")
    Rel(reader, cache, "Where is vehicle X and what state is it in?", "Valkey HGETALL")

    UpdateLayoutConfig($c4ShapeInRow="2", $c4BoundaryInRow="1")
```

## Level 2 — Container

```mermaid
C4Container
    title Container — what `just e2e` deploys on kind (namespace vehicle-cache)

    Container_Ext(writers, "Mock writers", ".NET 10 console (Jobs writers-seed, writers-scenario)", "e2e runs seed + scenario; vehicles / positions load modes exist but are not run by e2e; Npgsql only")
    Container_Ext(reader, "Verifier", ".NET 10 console (Jobs verifier-expect, verifier-dump)", "test oracle + canonical dump; stands in for cache readers")
    ContainerDb_Ext(pg, "PostgreSQL 17.6", "StatefulSet", "Operational DB: vehicles, positions; wal_level=logical; guard triggers")

    System_Boundary(b, "Vehicle Cache") {
        Container(register, "register-connector", "Job (curl)", "PUT /connectors/fleet/config, waits for RUNNING")
        Container(connect, "Kafka Connect + Debezium 3.2", "Deployment", "PostgreSQL connector, pgoutput, snapshot.mode=initial")
        ContainerQueue(kafka, "Kafka 3.9 (KRaft, 1 broker)", "StatefulSet", "fleet.public.vehicles, fleet.public.positions")
        Container(worker, "Vehicle Cache Worker", ".NET 10 BackgroundService (Deployment)", "Consumes CDC, conditional Lua writes, at-least-once")
        ContainerDb(valkey, "Valkey 8.1", "Deployment", "hash vehicle:{id}")
    }

    Rel(register, connect, "registers connector", "REST")
    Rel(writers, pg, "writes", "SQL")
    Rel(connect, pg, "reads WAL via replication slot", "pgoutput")
    Rel(connect, kafka, "produces change events", "JSON, key=id / vehicle_id")
    Rel(worker, kafka, "consumes, stores offsets after write", "Confluent.Kafka")
    Rel(worker, valkey, "EVALSHA conditional scripts", "StackExchange.Redis")
    Rel(reader, valkey, "SCAN / HGETALL", "RESP")
    Rel(reader, pg, "oracle query (test harness only)", "SQL")

    UpdateLayoutConfig($c4ShapeInRow="3", $c4BoundaryInRow="1")
```

> There is intentionally **no edge from the Worker to PostgreSQL**. The only reader of Postgres besides Debezium is the verifier, which is the test oracle.

## Level 3 — Component (Worker)

```mermaid
C4Component
    title Component — Vehicle Cache Worker

    ContainerQueue(kafka, "Kafka", "", "two CDC topics")
    ContainerDb(valkey, "Valkey", "", "vehicle:{id}")

    Container_Boundary(w, "Worker") {
        Component(cv, "Vehicles consumer", "KafkaCdcConsumer", "fleet.public.vehicles; StoreOffset after the handler returns; poison ⇒ stop host")
        Component(cp, "Positions consumer", "KafkaCdcConsumer", "fleet.public.positions; same contract")
        Component(handler, "CdcRecordHandler", "Worker", "map → write; bounded retry of idempotent writes; poison is rethrown")
        Component(map, "Change mappers", "Projection (pure)", "Debezium envelope (internal parser) → UpsertState / ApplyPosition / DeleteVehicle / Skip")
        Component(writer, "ValkeyVehicleCacheWriter", "Worker", "runs the command's Lua guard; Applied / Rejected / Skipped")
        Component(lua, "Lua guards", "apply_state / apply_position / delete_vehicle", "ordering + idempotency + tombstone, atomic per key")
        Component(metrics, "ProjectionMetrics", "logs", "applied / rejected / skipped counters — never in Valkey")
    }

    Rel(kafka, cv, "poll")
    Rel(kafka, cp, "poll")
    Rel(cv, handler, "record value")
    Rel(cp, handler, "record value")
    Rel(handler, map, "bytes")
    Rel(handler, writer, "CacheCommand")
    Rel(handler, metrics, "outcome")
    Rel(writer, lua, "EVALSHA")
    Rel(lua, valkey, "HMGET/HGET + HSET/DEL")
```

## Runtime view — the hard cases (sequence)

```mermaid
sequenceDiagram
    participant P as positions topic
    participant V as vehicles topic
    participant W as Worker
    participant K as Valkey vehicle:7
    P->>W: pos id=10 recorded 10:05 (vehicle 7 unknown yet)
    W->>K: apply_position → 1 (hash has only position)
    V->>W: insert vehicle 7 v1 ACTIVE
    W->>K: apply_state → 1 (joined)
    P->>W: pos id=11 recorded 10:01 (late GPS)
    W->>K: apply_position → 0 (stale, (10:01,11) < (10:05,10))
    V->>W: update v2 IDLE (redelivered twice)
    W->>K: apply_state → 1, then → 0 (duplicate)
    V->>W: delete 7
    W->>K: delete_vehicle → 1 (tombstone)
    P->>W: pos id=12 recorded 10:09
    W->>K: apply_position → 0 (deleted is absorbing)
```
